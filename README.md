# EarLab — центр управления Bluetooth-наушниками для Android

Kotlin + Jetpack Compose, minSdk 26 (Android 8.0), targetSdk 35. Работает с любыми Bluetooth-наушниками.

## Что умеет

**Главная**
- Кольцо заряда, статус подключения, «в сети N часов назад»
- Прогноз времени работы: считается по реальному расходу заряда (только за активное время)
- График заряда за 48 часов
- Статистика: сколько слушали сегодня и за 7 дней, столбики по дням

**Звук**
- Эквалайзер: кривую правят пальцем (5 точек: 60 Гц … 14 кГц), пересчёт на любое число полос устройства
- Бас, «Объём» (виртуализатор), «Громкость+» (до +8 дБ)
- 8 готовых пресетов + свои (сохранить / удалить)

**Авто** (отдельно для каждых наушников)
- При подключении: включить пресет, выставить громкость, запустить музыку
- Уведомление о низком заряде (порог настраивается)
- Напоминание дать ушам отдохнуть (30 / 45 / 60 / 90 мин)

**Поиск**
- Запоминает место, где наушники отключились → «Открыть на карте»
- Радар «тепло — холодно» по силе Bluetooth-сигнала (LE)
- «Позвонить в наушники»: писк с плавным нарастанием громкости

## Как собрать

1. Установите Android Studio (Ladybug 2024.2 или новее) и откройте папку `EarLab`.
2. Дождитесь Gradle Sync (нужен интернет для загрузки зависимостей), Android SDK 35 подтянется сам.
3. Подключите телефон (отладка по USB) и нажмите ▶ Run.

Командная строка: `./gradlew assembleDebug` → `app/build/outputs/apk/debug/app-debug.apk`.

### Сборка APK через GitHub (без Android Studio)

1. Создайте репозиторий на github.com и загрузите в него содержимое папки `EarLab`
   (вместе со скрытой папкой `.github`).
2. Откройте вкладку **Actions** → **Build APK** → **Run workflow** (или просто сделайте push — сборка стартует сама).
3. Через 3–6 минут откройте завершённый запуск → внизу, в разделе **Artifacts**, скачайте `EarLab-debug-apk`.
4. Распакуйте zip, перенесите `app-debug.apk` на телефон и установите (разрешите установку из неизвестных источников).

Если сборка упала, откройте шаг «Сборка debug APK» — там текст ошибки компилятора.

> ⚠️ Проект написан без возможности собрать его на месте (нет Android SDK). Если Gradle или компилятор
> укажут на ошибку — это, скорее всего, мелочь вроде опечатки или импорта; пришлите текст ошибки, и я исправлю.

## Что важно знать (ограничения Android)

| Функция | Ограничение |
|---|---|
| Заряд | Берётся из системы. Если наушники не передают его по стандартным каналам (HFP / Battery Service), будет «—». У некоторых брендов (AirPods, Galaxy Buds, Sony и др.) заряд виден; у части китайских — нет. |
| Шумоподавление, жесты, «прозрачный режим» | Недоступны: у каждого бренда закрытый протокол. Для конкретной модели можно дописать отдельным модулем. |
| Эквалайзер | Применяется к глобальной аудиосессии. На части телефонов/прошивок система её игнорирует — тогда приложение скажет об этом. Плееры, которые открывают сессию эффектов (VLC и др.), подхватываются отдельно. YouTube / Spotify на многих устройствах обходят системные эффекты. |
| Радар | Работает только с наушниками, принимающими LE-соединение. Если не подключился — приложение сообщит. |
| Геолокация | Сохраняется положение *телефона* в момент отключения — это подсказка, не точное место наушников. Данные хранятся только на устройстве. |
| Автозапуск музыки | Отправляет плееру команду «Play». Если плеер не реагирует на медиа-кнопки — не сработает. |
| Фоновая служба | Для работы в фоне показывает постоянное уведомление (требование Android). На некоторых прошивках (Xiaomi, Huawei, Samsung) стоит отключить для EarLab «оптимизацию батареи». |

## Структура

```
app/src/main/java/com/earlab/app/
├── EarLabApp.kt            Application, хранилище
├── data/                   Модели, Store (JSON в SharedPreferences), аналитика
├── bt/                     BtMonitor (подключения + заряд), Radar (RSSI по GATT)
├── audio/                  EffectsManager (EQ/бас/объём), PingTone
├── service/                KeepAliveService, BootReceiver, Notifier
├── util/                   Perms, LocationHelper
└── ui/                     Compose-экраны, ViewModel, компоненты
```
